什么是 AI Agent

Agent = 会用工具完成目标的 AI。它不只回答，还会根据结果决定下一步，直到完成或停止。

PART 01 · 一句话

Agent 是“完成任务”的程序

输入目标，输出完成结果

普通聊天机器人主要输出文字；Agent 可以读取信息、调用工具并验证结果。

目标
“整理下载目录，只保留 PDF”用户给的是结果，不必指定每一步。
↓
Agent
自己拆步骤、选择工具、根据结果调整核心不是“聪明回答”，而是“下一步能继续做”。
↓
结果
目录已整理，并报告保留和删除了什么结果必须可检查，不是只说“完成了”。
PART 02 · 循环

它靠循环，而不是一次回答

每次行动后，都先看结果

结果不符合预期时，Agent 换一个步骤；完成时才停止。

一个最小 Agent 循环
收到目标
while 未完成 且 未超时:
  下一步 = LLM 根据目标和已有结果决定
  结果 = 调用工具(下一步)
  把结果交给 LLM
返回最终结果
四个词：目标 → 决定 → 执行 → 观察。观察后的信息会影响下一次决定。

目标

要完成什么

例如“查 Redis 是否有慢查询”。

工具

能做什么

读文件、执行命令、搜索网页、调用 API。

停止条件

何时结束

完成、失败、超时或达到最大步数。

PART 03 · 例子

目标：找出 Redis 的慢命令

一次任务会怎样执行

这个例子中，Agent 不知道答案；它通过工具一步步获得答案。

1

决定

先检查慢日志是否开启，以及是否有记录。

2

执行

调用 redis-cli SLOWLOG GET 10。

3

观察

看到 KEYS * 多次出现，耗时最高。

4

继续处理

解释风险，并建议用 SCAN 替代。

结果最终回答应包含证据

发现：最近 10 条慢命令中有 6 条是 KEYS *。
建议：用 SCAN 分批遍历，避免阻塞 Redis 主线程。

PART 04 · 区别

普通 LLM 和 Agent 的差别

模型负责决定，程序负责执行

Agent 通常以 LLM 为“大脑”，再加工具、循环和停止条件。

普通 LLMAgent
输入一个问题一个目标
输出一段文字文字 + 工具执行结果
下一步通常等待用户再问根据工具结果自己继续
边界不能直接影响外部系统权限范围内可读写、调用 API、执行命令
不要误解：Agent 不等于“永远正确”。它只是能执行多步任务；工具权限、验证和停止条件仍然需要设计。
