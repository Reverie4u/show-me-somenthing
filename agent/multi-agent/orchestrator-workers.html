PART 01 · 是什么

主管规划，工人执行

一个主任务拆成多个子任务

主管 LLM 动态拆解目标、把每个子任务分给一个 worker，再汇总各 worker 结果。

Orchestrator
拆解 + 分派 + 汇总决定任务、数量与顺序。
↓
Workers
各自执行一个独立子任务只做自己的部分。
↓
结果
合并成最终输出
PART 02 · 对比

与顺序/静态流程

动态 vs 预定

Orchestrator-Workers 是“动态规划 + 并行”，不同于静态写死的 workflow 或纯串行。

Orchestrator-Workers静态 workflow
分派LLM 动态决定代码写死
并行可并行通常串行
适合子任务边界清晰、可独立流程固定、需确定
PART 03 · 边界

独立与汇总

子任务要真独立

worker 之间强依赖或共享可变状态时，并行会出错；必要时让 worker 只读、结果集中汇总。

出处：Anthropic《Building Effective Agents》把 orchestrator-workers 列为一种 workflow（一个中心 LLM 拆解并分派、多个 worker 并行执行）。
