Plan-and-Execute

面对复杂任务，先让模型站在全局把步骤列清楚，再按计划逐步执行；每一步做完都检查是否需要调整计划。

PART 01 · 是什么

把“想清楚”和“动手做”分成两段

先看地图，再出发

ReAct 是“边走边问路”，Plan-and-Execute 是“出发前先看地图”。它能避免 ReAct 的循环漂移。

Planner
生成分步计划，只规划不执行
↓
Executor
按计划逐步执行，每步可用 ReAct 跑
↓
Re-planner
每步后判断计划是否仍适用
出处说明：“规划/执行分离”是工程范式，可溯源到 ReAct 论文 对“计划不足导致漂移”的讨论，以及 Anthropic《Building Effective Agents》 对 workflow 编排（预先编排 vs 模型驱动）的区分；作为命名范式多来自框架文档，故标注为工程实践。
PART 02 · 分工

三个角色各司其职

规划只做一遍，执行分步落地

规划用更强模型保证方向，执行用更便宜模型控制成本。

Planner

想清楚

接收目标，输出有序步骤列表；这一步不调用任何工具。

Executor

动手做

按步骤执行；每步把之前的结果作为 context，知道做到哪了、不迷路。

Re-planner

盯全局

每步后对照剩余计划，决定是否需要修正后续步骤。

关键：执行器知道自己在整个计划中的位置，这是和纯 ReAct 的本质差别——不会因为眼前线索就忘了整体目标。
PART 03 · 动态调整

计划不是死的

执行到一半，结果和预期不符怎么办

规定“每步都复盘”会多花调用；实践中常设触发条件，只在差异大或失败时重规划。

Replan 触发逻辑
for 每一步:
　结果 = 执行(当前步骤)
　if 结果与预期偏离大 或 有失败:
　　剩余 = LLM(原计划 + 已完成 + 新结果)　# 重规划剩余步骤
　继续下一轮
权衡：每步都 Replan 会线性增加调用次数；折中是设置条件触发，只在“步骤输出异常”或“执行失败”时启动，兼顾稳健与成本。
PART 04 · 搭配

两种模式常混合使用

全局用计划，局部用 ReAct

规划阶段抓方向，执行阶段抓灵活；两者不是替代，而是组合。

ReActPlan-and-Execute
决策方式每步临时先全局规划
易漂移是否，有全局视野
适合开放/探索任务目标明确的多步任务
成本历史线性增长多一次初始规划调用
常见做法：规划用大模型、执行用较便宜的小模型；工程上常把复杂任务拆解后并行执行独立子任务，降低端到端延迟。
