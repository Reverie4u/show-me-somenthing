PART 01 · 是什么

一个“生成→评估→改进”的循环

和 ReAct 的区别：它是“回头看”，不是“往前走”

ReAct 每步看下一步该做什么；Reflection 在产出后回过头审视输出质量，决定要不要重来。

生成
先给出一个输出
↓
评估
自评或外部判据检查是否达标
↓
改进
把反馈写回，重新生成一轮
要点：必须有一个“PASS / 够了就停”的出口，否则会无限循环。
PART 02 · 一手

两个代表工作

用语言反馈来迭代，而不是梯度

都强调“反馈来自语言/自我评估”，而非传统的强化学习奖励。

Reflexion

论文 · arXiv:2303.11366

语言 Agent 用言语强化学习：把失败经验总结成文字反馈，存入记忆，下轮避开同样的错。

Self-Refine

论文 · arXiv:2303.17651

同一模型给出初始输出，再自我反馈 + 精炼多轮，逐步提升输出质量。

出处：Shinn et al.，Reflexion: Language Agents with Verbal Reinforcement Learning(2023)；Madaan et al.，Self-Refine: Iterative Refinement with Self-Feedback(2023)。
PART 03 · 实现

循环要能停

三条退出方式

避免“改到天荒地老”：达标、达到上限、明确失败都算停止。

反思循环
for 轮次 in 1..最大轮次:
　输出 = LLM(任务 + 历史反馈)
　判定 = 评估(输出)
　if 判定 == 通过: 返回输出
　历史反馈 += 评估给的改进建议
返回 “达到上限，最好的一次输出”
停止条件：通过 / 到最大轮次 / 连续不改进三者之一，缺一个都可能卡死。
PART 04 · 取舍

什么时候用反思

有明确可评判标准时最有效

能用自动测试、结构化校验、明确打分判断“好不好”的场景，反思收益大。

场景是否适合反思
代码、有测试可判很适合，用测试结果作反馈
翻译、润色适合，模型能自评
主观且难测优劣慎用，容易反复无意义
成本每轮多一次评估调用，注意预算
叠加：反思常和 ReAct / Plan-and-Execute 组合：执行中或收尾时加一层“评估→改进”，提升最终质量。
