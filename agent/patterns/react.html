PART 01 · 是什么

一个“思考→行动→观察”的循环

三条信息交替出现

一手定义来自 ReAct 论文：让模型交替生成推理轨迹与任务动作，推理为行动指方向，行动为推理供事实。

Thought
分析当前局势，决定下一步
↓
Action
调用工具，携带参数
↓
Observation
工具返回的真实结果，回到 Thought

Thought

模型生成

分析当前局势，决定下一步做什么。

Action

模型生成

选哪个工具、填什么参数。

Observation

代码填回

工具返回的真实结果，成为下一步的依据。

出处：Yao et al., 《ReAct: Synergizing Reasoning and Acting in Language Models》(2022)，arXiv:2210.03629。核心是“交错生成推理与行动”。
PART 02 · 对比

CoT 只能推理，ReAct 能行动

两代推理模式

CoT 让模型把推理写出来；ReAct 在推理链里插入真实的工具调用。

CoTReAct
推理纯文字显式化推理与行动混杂
外部交互不能主动获取每步可调工具
数据来源训练知识实时/真实结果
局限无法拿实时数据会漂移、错传
出处：CoT 见 Wei et al. (2022)，arXiv:2201.11903；ReAct 针对其“纯推理”局限提出。论文指出 ReAct 在需多跳问答的基准上明显优于 Act-only（只行动不推理）。
PART 03 · 实现

模型负责输出，代码负责驱动

循环不是模型自己在转

模型每次只输出下一步的 Thought 与 Action；你的代码解析动作、执行工具、把 Observation 填回历史，再交给模型。

最小驱动循环
while 未到最大步数:
　resp = LLM(历史 + 问题)
　if 出现 Final Answer: 返回答案
　action, args = 解析(resp)
　obs = 执行工具(action, args)　# 真正的执行在代码里
　历史 += [resp, 装填 Observation]
返回 “超过最大步数，未完成”
关键分工：模型只做决策（选工具、填参数），真正执行与结果回填由代码负责。现代模型可用结构化 tool_calls 直接输出，不再靠解析文本格式。
PART 04 · 局限

两个实战坑

适合边界不明确的任务，但代价是漂移

任务越开放，ReAct 越灵活；没有全局计划，容易跑偏。

循环漂移

失去全局目标

每步都按当前历史临时决策，步骤一多、历史一长，可能被岔路带走。

错误传播

前向无纠偏

某一步拿到错的数据，后面推理全被带偏；ReAct 不回看前面步骤是否靠谱。

选型

何时用

开放问答、信息搜索等探索型任务；目标明确的多步任务建议用 Plan-and-Execute。

演进：这两个根因都是“纯前向、无全局规划”。下一篇 Plan-and-Execute 用“先规划再执行”补上全局视野。
PART 05 · 案例

真实项目里怎么用

已是众多 Agent 的通用骨架

“思考→行动→观察”循环成为客服、编码等 Agent 的默认做法；以下为官方文档提到的案例。

编码 Agent

落地 · Anthropic

用 agent 循环解决 SWE-bench 任务：根据环境反馈（如测试结果）决定下一步，而非一次性生成。

客服 Agent

落地 · Anthropic

把工具调用接入订单、知识库，以“用户问题是否解决”作为成功标准；正是 ReAct 式工具循环的典型。
