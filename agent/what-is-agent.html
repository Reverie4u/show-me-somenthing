PART 01 · 定义

什么是 Agent

一句话定义

Agent 执行的是一个任务，而不只是回答一句话。

Agent 是一个能自己决定下一步做什么的 AI 程序：它拿到一个目标，自己拆解任务、调用工具、观察结果，然后继续决定下一步，直到完成目标。

这个模式叫自主闭环——感知 → 规划 → 行动 → 再感知。所以它与"问答式"LLM 的区别不在模型，而在循环。
PART 02 · 循环

核心机制：Agent 循环

四步闭环

每一步之间都会回到"思考"，因为上一步的结果是下一步的输入。

1

输入

目标 / 指令，例如"查一下今天的 Redis 集群状态"。

2

思考

LLM 生成下一步：决定"先看看有哪些节点"。

3

行动

调用工具，执行 redis-cli info 之类的操作——工具不决策，只执行。

4

观察

把工具输出喂回给 LLM，作为下一轮思考的输入。

什么时候停下来：任务完成 / 达到最大轮数 / 超时 / LLM 主动结束——生产环境里停止条件是必须配置的。
PART 03 · 支撑

支撑自主闭环的三样东西

工具调用

决策与执行分离

从"说话"变"做事"：模型决定做什么，程序负责真正执行（命令、读写文件、搜索、调 API）。

记忆

短期 + 长期

短期 = 当前对话上下文，容量有限；长期 = 向量库存偏好与历史，跨任务不忘。

多步推理与纠错

失败可重试

某步失败时分析原因、换方式重试，还能回头审视已完成的步骤。

PART 04 · 对比

Agent 与普通 LLM 的区别

普通 LLM / 聊天机器人Agent
知识 冻结：只到训练数据截止那刻 可用工具读取实时信息（搜索 / API / 文件）
行动 不能行动：只是文本生成器 会行动：执行命令、读写文件、调 API
状态 两次调用之间失忆 有记忆：短期上下文 + 长期向量库
结束 一次提问 → 一次回答，答完即止 围绕目标循环，直到完成或触达停止条件
1一个具体例子：清理账本文件
思考: 先看看文件有多大，再决定怎么清理
调用工具  Read  ledger.csv        → 看到 2.1 MB、有重复行
调用工具  Bash  python dedupe.py   → 清理成功，节省 400 KB
调用工具  Read  ledger.csv        → 确认清理结果正常
回答: 已清理，文件从 2.1 MB 降到 1.7 MB，重复行已删除

注意观察环节：第三步读完文件后并没有直接答复，而是把结果带回去继续思考——这就是"循环"在起作用。
