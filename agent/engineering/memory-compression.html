PART 01 · 为什么

窗口有限，历史会增长

不压缩就爆上下文

对话、工具结果、推理不断累积，成本与错误都随之上升；把不重要的历史压缩成摘要或只保留关键。

出处：LLM 上下文有限，见 MemGPT 的思路：在有限窗口内分层管理记忆。
PART 02 · 手段

摘要 / 压缩 / 检索

三种常见做法

可以组合使用：把历史浓缩、去重，或只把“相关”的部分取回。

摘要

浓缩事实

让模型把旧对话/结果总结成一段关键信息。

压缩

缩短 token

用 LLMLingua 类方法压缩提示，保留语义、减少 token；见 LLMLingua。

检索

按需取回

不全都塞入，只检索与当前相关的内容。

PART 03 · 权衡

压缩必有损

保关键、可回取

压缩会丢细节，可能丢重要信息；关键结论要保留，必要时能按需回取原文，并配校验。

工程实现 vs 一手定义：向量库/压缩是工程实现；记忆分层的一手代表是 MemGPT 与 Generative Agents。
