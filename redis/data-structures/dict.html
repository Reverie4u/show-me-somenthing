PART 03 · rehash

扩容或缩容时，一次只搬少量桶

为什么不能一次搬完

大表一次性 rehash 会阻塞 Redis 主线程。渐进式 rehash 把工作拆进后续操作中。

1

创建新表

扩容时通常选择更大的 2 的幂大小；缩容时选择更小的表。

2

迁移一个桶

把旧表当前桶里的所有 entry 按新表的桶号重新放置。

3

推进 rehashidx

跳过空桶，继续迁移下一个非空桶。

4

写操作进入新表

rehash 期间新增 key 只放入 ht[1]，避免来回搬动。

扩容：负载因子接近 1 时，通常需要更多桶以维持查找速度。

缩容：元素数量长期较少时，表可能收缩以回收桶数组内存。

读取时：先查 ht[0]，rehash 中找不到再查 ht[1]。
PART 04 · 使用

dict 在 Redis 中的主要位置

它不只是 Hash 的底层实现

看见“按名称或成员快速找内容”的需求，通常会遇到 dict。

主键空间

key → robj

数据库里的所有 key 放在 dict 中；key 通常是 SDS。

Hash

field → value

Hash 超过 listpack 阈值后使用 dict。

Set / ZSet

member → 信息

Set 用它判断成员；ZSet 用它按成员定位分数。
