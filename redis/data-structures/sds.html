PART 01 · 问题

C 字符串的问题，SDS 分别处理

C 字符串只靠 \0 判断结束

它没有保存长度和容量。很多操作都要从头扫描，或依赖调用者自己处理边界。

问题C 字符串SDS 的做法
取长度strlen 扫到 \0，O(n)直接读 len，O(1)
二进制数据中间的 \0 会被当成结束真实边界由 len 决定；\0 可作为普通数据保存
追加数据调用者负责确认目标空间足够先检查 alloc - len；不够就扩容

常见 C 函数为什么容易出问题

问题不是某一个函数，而是长度和容量不属于字符串对象本身。

操作典型函数风险SDS
取长度strlen必须遍历；若没有 \0，可能越界读读 len
写入strcpy / strcat不知道目标容量，可能越界写读 alloc 后再写
比较 / 查找strcmp / strstr在第一个 \0 提前停止按 len 比较全部字节
分词strtok内部保存状态，不可重入SDS 本身只保存数据，不保存遍历状态
1连续 strcat 为什么会慢
char *strcat(char *dest, const char *src) {
  size_t dlen = strlen(dest);  // 每次先扫描已有内容
  memcpy(dest + dlen, src, strlen(src) + 1);
  return dest;
}

循环追加 n 次时，dest 会越来越长，但每次都从头扫描一次。总成本可变成 O(n²)。SDS 直接用 len 找到写入位置。

2strncpy 不一定补上结束符
char buf[8];
strncpy(buf, "hello, world", 8);  // buf 没有 \0
printf("%s", buf);                // 会继续读 buf 后面的内存
  • 源字符串长度至少为 n 时，结果不会自动以 \0 结束。
  • 源字符串较短时，它会继续填充 \0。
  • 源字符串较长时会截断，调用者必须自己判断。
3strcmp 无法比较二进制内容
strcmp("abc\0def", "abc") == 0  // 被当作相等

strcmp 在第一个 \0 停止。二进制数据应先比较长度，再使用 memcmp；SDS 的比较也以 len 为准。

SDS 把长度和容量放在数据前面

内存布局：redis

一块连续内存

alloc1 B11

bufr e d i s

\0
↑ len 决定真实边界；alloc 决定能装多少；结尾的 \0 只用于兼容 C 字符串函数。

len

已使用字节数

不含末尾 \0。取长度 O(1)，也让 SDS 能保存内嵌 \0。

alloc

数据区总容量

不含头部与末尾 \0。剩余空间是 alloc - len。

flags

头部类型

低 3 位标记头部类型。Redis 据此知道 len / alloc 的字段宽度。

实现要点：头部结构体使用 __packed__，减少对齐填充；buf[] 是柔性数组，头部和数据一次分配、连续存放。

五种头部，按字符串长度选

短字符串不需要 8 字节长度字段；长字符串也不能只用 1 字节。SDS 让头部随长度变化。

类型头部len / alloc最大长度特点
sdshdr51 B长度存在 flags 高 5 位31 B没有 alloc，不能原地扩容
sdshdr83 B1 B + 1 B255 B短字符串
sdshdr165 B2 B + 2 B65,535 B中等字符串
sdshdr329 B4 B + 4 B4,294,967,295 B大字符串
sdshdr6417 B8 B + 8 B2⁶⁴ − 1 B超大字符串
sdshdr5 的特殊点：flags 的高 5 位存长度，低 3 位存类型。因此它没有单独的 alloc 字段；需要追加时会创建更大的 SDS，而不是在原地扩容。
PART 03 · 追加

SDS 用预分配减少重复扩容

hello 追加 world

初始：len=5、alloc=5。要追加的内容长度是 6 B。

1

检查空闲空间

alloc - len = 5 - 5 = 0。空闲 0 B，追加需要 6 B，所以不能直接写。

2

计算新容量

最少需要 5 + 6 = 11 B。小于 1 MB 时，SDS 将容量翻倍到 22 B。

实际还会计入头部与结尾 \0 的内存。
3

写数据，更新元数据

写完：len=11、alloc=22。后面还剩 11 B 可用。

扩容后的数据区
len11
alloc22
bufh e l l o · w o r l d
空闲 11 B
↑ 接下来追加不超过 11 B 时，不需要再次分配内存。
核心sdsMakeRoomFor 的判断
if (alloc - len >= addlen)
  return s;                  // 空间够，直接写

newlen = len + addlen;
if (newlen < 1MB)
  newlen *= 2;                 // 小于 1 MB：翻倍
else
  newlen += 1MB;               // 达到 1 MB：每次多留 1 MB

扩容那一次仍可能复制已有数据，成本是 O(n)。但多数追加会使用提前预留的空间，所以连续追加的平均成本是 O(1)。

缩短字符串时，空间通常先保留

这是惰性释放：减少频繁分配和释放内存，但也会暂时占着不用的空间。

需要真的释放时：调用 sdsRemoveFreeSpace()。它会把容量缩到接近当前长度。
PART 04 · 细节

兼容 C 生态，也服务 Redis 的多处存储

为什么 SDS 还保留结尾 \0

SDS 不依赖它判断边界，但保留它可以直接调用部分 C 字符串函数。

Qstrcasecmp 和 SDS 有什么关系？

strcasecmp 是 POSIX 的大小写不敏感字符串比较函数：SET、set、Set 会被视为相同。

  • SDS 的 buf 末尾有 \0，纯文本场景可以直接传给这类函数。
  • 它仍会在第一个 \0 停止，因此不能用来比较包含二进制数据的 SDS。
  • 二进制数据按 len 比较，例如使用 SDS 自己的比较函数。
Q为什么 sdshdr5 把长度放进 flags？

flags 的低 3 位本来就要记录头部类型。sdshdr5 把剩下的高 5 位用于存 len，所以 1 B 头部同时保存类型和长度。

+----------------+------------------+
| 高 5 位：len    | 低 3 位：type    |
| 0 ~ 31          | SDS_TYPE_5       |
+----------------+------------------+
  • 好处：长度不超过 31 B 的字符串只用 1 B 头部。
  • 代价：没有 alloc，没有可复用的空闲空间。
  • 一旦要追加，Redis 会换成能保存 alloc 的更大头部；不会再换回 sdshdr5。
