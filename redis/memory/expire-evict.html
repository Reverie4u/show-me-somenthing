过期删除 与 内存淘汰

PART 02 · 过期

TTL 到期后，Redis 两种方式清掉

被动过期 + 主动过期

过期 key 没有「定时器」逐秒精确删除；Redis 靠「被访问时检查 + 周期抽样」来兜底。

被动过期

惰性 · 访问时删

访问 key（如 GET）时检查是否过期，过期就当场删掉并返回不存在。省 CPU，但不常访问的 key 会一直占内存。

主动过期

周期采样

后台随机采样带 TTL 的 key，删掉已过期的，避免惰性策略导致过期 key 堆积。Redis 6 增加 radix tree 记录「快要过期」的 key，让下一轮采样更快。

要点：设置过期靠 EXPIRE/PEXPIREAT/SET EX 等命令；删除则只靠上面两种机制。过期 key 不是「到点立刻消失」，而是「逻辑上不可见 + 内存稍后释放」。从读取角度看，过期即不可见。
PART 03 · 淘汰

内存到达上限，按策略选受害者

maxmemory 触发，策略决定删谁

与 TTL 无关。即使所有 key 都永不过期，内存满了照样要淘汰。

策略行为
noeviction不淘汰；写入报错。
allkeys-lru从所有 key 里淘汰最久没用的。
allkeys-lrm从所有 key 里淘汰最久没改过的（Redis 8.6+）。
allkeys-lfu从所有 key 里淘汰最不常用的。
allkeys-random从所有 key 里随机淘汰。
volatile-lru只从「设了 TTL」的 key 里淘汰最久没用的。
volatile-lrm只从「设了 TTL」的 key 里淘汰最久没改过的（Redis 8.6+）。
volatile-lfu只从「设了 TTL」的 key 里淘汰最不常用的。
volatile-random只从「设了 TTL」的 key 里随机淘汰。
volatile-ttl淘汰剩余 TTL 最短的 key。
关键：记忆时可拆成两半——「范围」选 allkeys 还是 volatile；「依据」选 lru / lrm / lfu / random / ttl。若没有任何 key 设了 TTL，volatile-* 策略行为等同 noeviction。
