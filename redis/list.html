PART 01 · 命令

从两端读写

List 的基本语义

成员保留顺序，允许重复；索引操作越靠近两端越快。

命令作用
LPUSH / RPUSH从左 / 右插入一个或多个元素。
LPOP / RPOP从左 / 右取出并删除元素。
LRANGE按索引范围读取；0 -1 表示全部。
BLPOP / BRPOP队列为空时阻塞等待元素。
LTRIM只保留一个索引区间，常用来保留最近 N 条。
PART 02 · 结构

quicklist：链表管理块，listpack 管理元素

为什么不是纯链表或纯数组

纯链表指针多；纯数组中间操作成本高。quicklist 把两者组合起来。

quicklist
双向链表快速定位头节点和尾节点。
↓
node
一个链表节点节点记录前后指针、元素数、压缩状态。
↓
listpack
连续字节块多个元素紧凑排列，少对象头和指针。
结果：头尾插入通常只修改首尾 listpack；需要新块时再挂一个节点。
PART 03 · 配置

两个参数控制内存和性能

节点大小与中间压缩

默认值适合大多数情况；只有明确的内存或访问模式问题时才调。

list-max-listpack-size

每个节点放多少数据

节点越大，指针开销越少；太大时移动或拆分一个节点的成本更高。

list-compress-depth

两端保留多少未压缩节点

中间节点可 LZF 压缩，节省内存；头尾节点保持未压缩，保证两端操作快。

访问中间元素

不是强项

LINDEX 50000 需要逐节点定位，不应当作随机访问数组使用。

PART 04 · 选择

List 适合队列和最近记录

使用边界

先看操作是“从两端进出”，还是“按成员查找”。

场景建议
任务队列LPUSH + BRPOP；需要可靠确认时优先评估 Stream。
最近 N 条LPUSH 后 LTRIM 0 N-1。
消息日志需要 ID、确认、重放和消费者组时使用 Stream。
按成员去重使用 Set，不要在 List 中线性查重。
