Redis · robj

robj —— 16 字节的对象外壳

数据库里每个 value 都包在一个 redisObject 里。它不负责任存数据：只回答三个问题——「这是什么类型」（type）、「用什么内存结构」（encoding）、「最近是否被访问、还有谁引用」（lru / refcount）。数据在哪，问 ptr。

PART 01 · 结构

16 字节是怎么拼出来的

位域字段，一个字节都不浪费

三个「小」字段用位域塞进同一个 4 字节里，加上 refcount 和 ptr，正好 16 字节——约等于两个指针的开销。

type4 bitOBJ_STRING
encoding4 bitEMBSTR
lru24 bit时间戳
refcount4 B3
ptr8 B▶
…4+4+24 = 32 bit
↑ 前面 4 字节是位域打包：type 4 bit + encoding 4 bit + lru 24 bit；中间 refcount 4 字节；最后 ptr 8 字节 —— 共 16 字节
type + refcount encoding lru ptr · 指向数据 
typedef struct redisObject {
    unsigned type:4;      /* 语义类型：OBJ_STRING / OBJ_LIST / OBJ_HASH ... */
    unsigned encoding:4;  /* 内存编码：INT / EMBSTR / RAW / LISTPACK / SKIPLIST ... */
    unsigned lru:24;      /* LRU 时间戳或 LFU 计数器 · 淘汰算法用 */
    int refcount;         /* 引用计数 · 共享对象用 */
    void *ptr;            /* 8 字节 · 指向真实数据（或就是数据本身） */
} robj;
「位域 + refcount + 指针」是每个 value 的固定开销：16 字节——换来所有 value 统一的生命周期管理（淘汰看 lru、共享看 refcount、命令分派看 type）。
PART 02 · 字段

四个字段，各司其职

type

4 bit · 语义类型

用户视角的「这是什么」：string、list、hash、set、zset。命令分派先看它——LPUSH 绝不会作用在 string 上。这个字段定义了「类型体系」本身：核心类型就这 5 个，stream 是后来加的第 6 个，插件（模块）还能自定义。

encoding

4 bit · 内存编码

实现细节的「存成什么样」：同样 type=STRING，短的纯数字可以是 INT、短文本 EMBSTR、长内容 RAW——命令一个样，底层内存结构差别迥异。OBJECT ENCODING 命令返回的就是它。编码详情见 PART 03 表。

lru + refcount

24 bit + 32 bit · 生命周期

lru 记录最近访问时刻（LRU / LFU 淘汰算法决策用）；refcount 让共享成为可能——见 PART 04「共享整数表」。它们与数据本身无关，属于统一的生命周期管理。

类型 × 编码 × 底层结构

同一张「类型 × 编码」全景图

这张表贯穿全部笔记：type 决定命令行为（横向一行），encoding 决定内存形态（横向一格）。每个类型页从自己的行讲起，共享结构页横向复用。

type可选 encoding底层结构何时选
string int / embstr / raw 无（值内联） / SDS 数字≤20字符 → int；≤44字节 → embstr；其余 → raw。见 string.html
list quicklist 双向链表 + listpack 节点 所有 list 统一 quicklist（7.0 起）。见 list.html
hash listpack / hashtable listpack / dict 字段数 < 128 且值 < 64 B → listpack；否则 dict。见 hash.html

PART 04 · 指针

ptr 的两种用法 · 共享整数

ptr 字段的两个世界观

ptr 是「数据在哪」的答案，但答案可能不是地址——这取决于 encoding。

① int 编码——值本身塞进指针（storage in pointer）
ptr 字段(void*)12345这「不是」地址，就是整数本身
读取时 (long long)ptr 直接取回 12345——零额外 malloc、零间接寻址。整个 robj 16 字节即全部，这也是 INCR 快的秘密
② embstr / raw 编码——ptr 指向外部数据
ptr 字段——▶
指向SDS / 结构体真正的一个内存地址
数据活在别处（embstr 与 robj 同块、raw 分两块），读值要 ptr → SDS → 数据两跳
为什么 int 能内联、字符串不行？long long 恰好 8 字节 = 指针宽度，值可以完整装进 ptr 字段；字符串可长可短（"a" 到 10MB），装不下，只能让 ptr 指出去。这就是「小对象内联」的判据：宽度等于一个指针、创建后不变的东西，就地嵌进去，别绕一圈找外面的地址。
共享整数：0 ~ 9999 不必各持一份

server 启动时预建 0~9999 的 10000 个共享 robj（OBJ_SHARED_INTEGERS）。命令产生的小整数（如 INCR counter 的结果）不新建对象，而是直接复用共享表里的现成对象、refcount +1；引用归零才真正释放。于是同一个 1 出现在 100 万个 key 里，内存里只有这 1 份。

生命周期提示：共享对象 refcount 只增不减到 0（永不可销毁，因为共享表一直持有引用）——这是 refcount 机制里唯一的「特权对象」。
