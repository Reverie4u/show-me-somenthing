Redis · listpack

listpack：一块连续内存装很多短值

listpack 是 Redis 的紧凑编码结构。它用类型前缀和长度信息保存多个字符串或整数，避免为每个元素分配对象和指针。

PART 01 · 目的

短值很多时，指针和对象头很贵

紧凑编码减少固定开销

例如 Hash 只有几个短 field/value 时，dict 的桶、entry、SDS 指针往往比实际数据还大。

dictlistpack
元素位置多个独立分配一块连续内存
元数据指针、对象头、桶每个条目的编码和长度
查找平均 O(1)顺序扫描 O(n)
适合大对象小对象、短值
PART 02 · 布局

头部、若干条目、一个结束标志

listpack 是连续字节数组

头部记录总字节数和元素数；最后一个字节 0xFF 表示结束。

整体布局
total-bytes4 B
num-elements2 B
entry 1 · entry 2 · …变长
0xFF
↑ 每个 entry 自己保存类型、数据和 backlen。
PART 03 · 条目

从前读类型，从后读 backlen

一个条目包含三部分

整数用更短的二进制形式；字符串记录长度后保存原始字节。

encoding
第一个字节的位模式区分 7-bit 整数、13-bit 整数、6-bit 字符串长度等。
↓
data
实际值整数可直接内联；字符串保存字节内容。
↓
backlen
条目编码长度的反向变长表示从尾部也能找到上一个 entry。
值编码例子
0 到 127 的整数1 B 直接保存。
长度小于 64 的字符串1 B 长度前缀 + 数据。
长度小于 4096 的字符串2 B 长度前缀 + 数据。
更长字符串5 B 长度前缀 + 数据。
backlen 的作用：ziplist 依赖前一个条目长度，可能触发连锁更新；listpack 把自身长度放在尾部，逆向遍历不需要修改后续条目。
PART 04 · 使用

多个小对象的起始编码

哪些类型会用 listpack

达到对应阈值后，Redis 会转换到更适合大对象的结构。

Hash

field / value 交替

小 Hash 用 listpack；大 Hash 转 dict。

ZSet

member / score 交替

小 ZSet 用 listpack；大 ZSet 转 skiplist + dict。

List / Stream

节点或消息块

quicklist 节点和 Stream 消息块内部使用 listpack。
