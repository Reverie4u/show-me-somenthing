PART 01 · 是什么

Set 概述

无序 + 唯一 + 运算

特点：无序、成员唯一、自带并 / 交 / 差 / 随机抽样。重复 SADD 同一个成员不会产生第二条。

语义命令
增删 / 判断SADD · SREM · SISMEMBER · SMISMEMBER（批量判断）
取出 / 扫描SMEMBERS（一次全量，慎用）· SCARD · SSCAN（游标）
集合运算SINTER · SUNION · SDIFF · SINTERSTORE（存结果）/ SINTERCARD（只数）
随机SPOP（随机取并删除）· SRANDMEMBER（只取不删）；都是真随机（随机下标 / 随机桶）
PART 02 · 编码

intset → dict：两阶段

切换条件

intset 编码dict 编码
元素形态 全部元素是整数（long long） 任意
规模 set-max-intset-entries（默认 512）个以内 超过 512 个，或进来字符串
内部实现 有序整数数组（见 PART 03） 哈希表：成员就是 dictEntry.key（以 SDS 存取）
「小对象用紧凑结构、大了换哈希/跳表」是三家的共同设计：hash（listpack→dict）、zset（listpack→跳表+dict）、set（intset→dict）。set 最简：listpack 内部还有编码字节和尾部长度，intset 就一个「头部 + 升序数组」——SADD 42 即数组里放 42，占 2 字节（int16 宽度）。
PART 03 · intset

有序整数数组，每元素 2/4/8 字节

布局与查找

intset 布局（intset.h）
encoding4 B2/4/8
length4 Bn
contents[]int16 | int32 | int64 —— 升序，紧凑
↑ encoding 记录元素宽度（2/4/8），按最大元素挑：{1, 2, 100000000} 用 4 字节，{1, 2, 256} 用 2 字节。
为什么这两个字段都用 4 字节：代码里就是 uint32_t。encoding 只存 2/4/8，1 字节其实放得下，但没必要分开处理；length 存元素个数，上限 42 亿——默认 512 只是配置（set-max-intset-entries 可调大），想调多大都装得下。同宽的好处：读写、转换一套代码，结构总长固定。花销：8 字节头，只存一个元素也才 10 字节，仍低于 dict 一个成员的几十字节。
查找：升序数组 → 二分（O(log n)）

升序是插入时维护的：新整数先找到位置，后面的元素后移一位再放进去（顺便判重）。于是 contents 永远升序，查找就能二分：取中点比较，一次排除一半，最多 ⌈log₂n⌉ 次。

查 7：
  [2, 5, 7, 19, 42]   min=0  mid=2  max=4 → contents[mid]=7，命中 ✓

查 8（不存在）：
  [2, 5, 7, 19, 42]   mid=7，8 > 7  → 右半区，min = mid+1
        [19, 42]      mid=19，8 < 19 → 左半区，max = mid-1
        []            空 → 不存在
static uint8_t intsetSearch(intset *is, int64_t value, uint32_t *pos) {
    int min = 0, max = intrev32ifbe(is->length) - 1, mid = -1;
    int64_t cur = -1;

    if (intrev32ifbe(is->length) == 0) { if (pos) *pos = 0; return 0; }  // 空表特判

    while (max >= min) {              // 标准二分骨架
        mid = (min + max) / 2;
        cur = _intsetGet(is, mid);    // 按 encoding 宽度解码出中点值
        if (value > cur)       min = mid + 1;
        else if (value < cur) max = mid - 1;
        else break;                  // 相等 → 是成员
    }
    // *pos 顺带算出该插入的位置：SADD 判重与插入共用一次定位
    if (pos) *pos = (value == cur) ? mid : (value > cur ? mid + 1 : mid);
    return (value == cur);
}

uint8_t intsetFind(intset *is, int64_t value) {
    if (intsetValueEncoding(value) > is->encoding) return 0;  // 剪枝：值比表宽大，必不存在
    return intsetSearch(is, value);
}

SPOP 的"随机"也是数组下标：随机取一个下标 → 取出该元素，后面的元素整体前移保持升序。

为什么 512 个以内不换哈希：dict 均摊 O(1)，但要先算哈希、走桶和链；intset 最多比 9 次就够，且每元素只有 2/4/8 字节（dict 版是 dictEntry + SDS，几十字节起）。小规模下更简单，也更快更省。
1升级：装不下就整体换宽

已有 {1, 2, 1000000}（int32 宽度），SADD 2147483648（超过 int32）装不下 → 整体升级：重新分配为新宽度，旧元素从尾部向前逐一转换（腾插入位）。升级后永不降级：删掉所有大整数也不缩回 int16。升级是一次 O(n) 的整块重写；n ≤ 512，微秒级。

对比 String 的 int 编码：String 把整数内联进 robj 指针（整个对象 16 字节）；intset 是"集合型"，每成员 2~8 字节。同样存数字，摆放不同。

SINTER 在这种形态下

按小集合内扫

交集：取最小的集合，逐元素查「是否在其他集合里」。intset 用二分，dict 用哈希。命令层不关心编码。

PART 04 · 场景

使用姿势

场景与注意事项

几个常见组合，都来自上面提到的「成员唯一 / 随机 / 运算」三种能力。

标签系统：SADD user:123 tag:a tag:b 判存在：SISMEMBER / SMISMEMBER 随机推荐：SRANDMEMBER 1 统计一组：SCARD 集合计算：共同好友 = SINTER，粉丝差集 = SDIFF
三件事
  • 别用 SMEMBERS 一次拉全量（百万成员会打爆客户端）；用 SSCAN 扫，或 SINTERSTORE 存成 key。
  • 成员就是字节串（同 String 的 value），大成员照样存成 SDS。
  • 并 / 交结果要反复用就先 STORE 存起来，别每次在客户端拼。
