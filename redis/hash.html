Redis · Hash

Hash：一个 key 下的一组 field → value

Hash 适合表示一个对象的多个字段，例如用户资料。小 Hash 用 listpack 省内存；变大后改用 dict 加快查找。

PART 01 · 命令

按字段读写

一个 Hash 像一条对象记录

field 唯一，value 是字节串；不同 field 可以独立更新。

命令作用
HSET user:1 name Ada设置一个或多个 field。
HGET / HMGET读取一个或多个 field。
HINCRBY对 field 中的整数做增减。
HGETALL读取全部 field 和 value；大对象慎用。
HSCAN用游标分批遍历大 Hash。
PART 02 · 编码

先 listpack，变大后 dict

切换条件

阈值由配置控制，默认值强调小对象的内存效率。

小 Hash
listpackfield 与 value 连续存放。默认 field 数不超过 128，且任一值不超过 64 B。
超出阈值 ↓
大 Hash
dictfield 作为哈希表 key，查找平均 O(1)。
↓
不会缩回
保持 dict删除字段后通常也不转回 listpack。
PART 03 · 原因

小对象先省内存，大对象再优化查找

两种编码的取舍

复杂度不是唯一指标；小对象时，指针和对象头的成本很明显。

listpackdict
内存连续编码，几乎没有指针dictEntry、SDS 和桶数组带来额外开销
查找顺序扫描，O(n)平均 O(1)
适合字段少、字段短字段多，或经常按字段读取
listpack 的细节：它把许多短字符串和整数紧凑编码在一个连续块里。见 listpack.html。
PART 04 · 边界

把相关字段放在一个 Hash 中

什么时候使用

Hash 是对象字段模型，不是关系型数据库的替代品。

适合

用户资料 / 配置

一个对象多个字段，可按字段单独更新。

注意

过期按 key

不能只给某个 field 设置 TTL；过期的是整个 Hash key。

不要这样用

超大对象

把几万 field 塞进一个 Hash 会让迁移、删除和全量读取变重。
