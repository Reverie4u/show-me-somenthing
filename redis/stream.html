Stream：可追加、可重放的消息日志

Stream 是 Redis 的独立类型。消息带 ID，可从指定位置读取；消费组还能记录谁还没有确认消息。

PART 01 · 模型

每条消息都有递增 ID

ID 是 毫秒时间戳-序号

例如 1700000000000-0。同一毫秒内多条消息靠序号区分。

PART 02 · 命令

追加、读取、裁剪

基础操作

Stream 的读取位置由 ID 而不是数组索引表示。

命令作用
XADD orders * item book追加消息；* 让 Redis 自动生成 ID。
XRANGE orders - +按 ID 范围读取消息。
XREAD STREAMS orders 0从给定 ID 之后读取；可阻塞等待。
XTRIM orders MAXLEN ~ 10000限制日志长度，近似裁剪更快。
XDEL orders id删除指定消息；不重排其他 ID。
PART 03 · 消费组

消费组把消息分给不同消费者

读取后必须确认

消费组解决“谁处理了什么”和“失败的消息怎么办”。

1

创建组

XGROUP CREATE orders workers 0 指定从哪个 ID 开始。

2

读取新消息

XREADGROUP GROUP workers c1 … > 把新消息分给消费者 c1。

3

确认

处理成功后 XACK orders workers id。

4

恢复

未确认消息留在 PEL；其他消费者可用 XAUTOCLAIM 认领超时消息。

PEL：Pending Entries List，记录“已交付但未确认”的消息。

语义：默认是至少一次投递；消费者需要处理重复消息。

PART 04 · 选择

需要消息状态时，用 Stream

Stream 与 List 队列的区别

List 更简单；Stream 提供 ID、历史和消费者组。

ListStream
读取后POP 就删除消息仍保留，可重放
消费者没有确认状态PEL 记录未确认消息
顺序位置队头 / 队尾消息 ID
适合简单临时队列事件流、可靠消费、多消费者
底层：Stream 使用 rax 索引和 listpack 存消息块；它是独立类型，不是 List 的别名。
