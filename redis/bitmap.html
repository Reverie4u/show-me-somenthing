Bitmap：把 String 当作位数组

Bitmap 不是新数据类型。它仍是 String，只是把每个 bit 当成一个开关，用于大量布尔状态和位运算。

PART 01 · 模型

用户 ID 对应一个 bit

0 和 1 分别表示状态

例如第 42 位为 1 表示用户 42 今天登录过；0 表示没有记录。

bitmap:2026-08-29
bit 00
bit 11
bit 20
…
bit 421
↑ 1 个用户只占 1 bit；8 个用户才占 1 byte。
PART 02 · 命令

位的读、写、统计和组合

常用命令

bit offset 从 0 开始；Redis 自动扩展 String 来容纳更高的 offset。

命令作用
SETBIT k 42 1把第 42 位设为 1，返回旧值。
GETBIT k 42读取第 42 位；越界返回 0。
BITCOUNT k统计值为 1 的 bit 数量。
BITOP AND out a b两个位图逐位与、或、异或或取反。
BITPOS k 1查找第一个值为 1 的 bit 位置。
PART 03 · 案例

统计连续两天都活跃的用户数

用 AND 求交集

每天一张位图，同一个用户固定使用同一个 offset。

1

写当天登录

SETBIT active:day1 userId 1。

2

求交集

BITOP AND active:both active:day1 active:day2。

3

统计人数

BITCOUNT active:both 得到连续两天活跃用户数。

内存：1,000 万用户需要 1,000 万 bit，约 1.25 MB。

优势：交集计算在 Redis 内部做位运算，不必把用户 ID 传回应用层。

PART 04 · 边界

适合连续 ID，不适合稀疏大 offset

先算 offset，再决定是否使用

位图内存大小约等于最大 offset ÷ 8，而不是已设置 bit 的数量。

适合

用户 ID 连续

0 到 1,000 万的用户编号，内存大小可预测。

不适合

ID 很稀疏

只设置 offset=10 亿，也会分配约 119 MB 的 String。

不能做

查具体成员

BITCOUNT 只能数数量；需要成员列表时使用 Set。

底层：Bitmap 使用的是 String 的 SDS 存储；高 offset 会触发 SDS 扩容。见 sds.html。
